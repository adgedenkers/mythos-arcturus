## Known Issues / Lessons Learned

### Grinder Issues to Fix in Build Plans
1. **`_get_conn` pattern** — models frequently rewrite it with wrong env vars (DB_HOST, DB_USER, mythos_user). Must be spelled out EXACTLY in pass 1 instruction AND in mandatory_patterns. Even then, the review pass sometimes replaces it.
2. **`async def execute`** — models write `def execute` instead of `async def execute`. Must say "CRITICAL: async def" in every pass that touches execute.
3. **`await` on .run()** — composite skills forget `await` on `cls().run(request)`. Must be explicit in instructions.
4. **`SkillResponse` kwargs** — models invent kwargs like `success`, `message`, `text`, `ok`, `result`. The `skillresponse_signature` mandatory pattern helps but isn't always followed.
5. **`RealDictCursor` returns dicts** — models write `fetchone()[0]` instead of `fetchone()['id']`.
6. **`dotenv` path** — models write `load_dotenv('.env')` or path relative to skill file. Must be `load_dotenv('/opt/mythos/.env')`.
7. **Search term extraction** — needs whitespace normalization between each phrase removal, single-char word cleanup, and comprehensive filler word list.

### Architectural Notes
- All CLI symlinks go to `/opt/mythos/bin/` (adge-owned), NEVER `/usr/local/bin/` (root)
- PatchBase has NO dry-run support on disk (despite the version pasted earlier)
- `/tmp/last_patch_output.log` gets root-owned when patches use sudo — fix with `chown`
- `checkin_log` table has NO `mood` column — use `summary` for mood text, `checkin_type` for type
- `routines` table uses `title` NOT `name`
- `astro_natal_charts` PK is `chart_id` NOT `id`, body column is `object_name` NOT `body_name`
- `voice_memos.status` values are `'complete'` NOT `'completed'`

## What's Next

### Immediate: Planner Layer
The system that lets an LLM look at a requirement, pick patterns from the library, and generate its own build plan. Flow:
1. User describes a feature: "I need a way to track daily habits"
2. Planner LLM analyzes → decides it needs: SQL table, data skill, action skill, Telegram command
3. Planner outputs a build_plan.json with scaffolded passes
4. Grinder executes the plan
5. Skills deploy automatically

This is the step from "Claude designs every feature" to "the system designs features itself."
