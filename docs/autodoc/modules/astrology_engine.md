# Mythos Astrology Engine Module Documentation

## 1. Module Purpose
The Astrology Engine module provides a comprehensive system for generating, storing, and analyzing astrological charts. It supports natal chart generation, planetary position calculations, aspect interpretation, and data persistence in PostgreSQL. The module enables:
- Birth chart creation with geolocation support
- Swiss Ephemeris-based planetary position calculations
- Aspect and house cusp analysis
- Data normalization and storage in relational databases
- Chart comparison and reporting capabilities
- Integration with external data sources (e.g., astrotheme.com)

## 2. Architecture Overview
The module follows a layered architecture with distinct responsibilities:
1. **Data Input Layer**: 
   - `astro_chart_handler.py` handles user input parsing and chart generation
   - `chart_pipeline.py` sources birth data from external APIs

2. **Processing Layer**:
   - `astro_position.py` calculates planetary positions
   - `astrochart_cli_tool.py` generates full chart data
   - `astro_loader.py` processes and normalizes data

3. **Persistence Layer**:
   - `astro_schema.sql` defines PostgreSQL schema
   - `astro_loader.py` inserts data into database tables

4. **Analysis Layer**:
   - `astro_report.py` generates comparative reports
   - `aspects.json` provides aspect interpretation logic

Data flows through the system as:
User Input → Geolocation → Position Calculation → Chart Generation → Database Storage → Analysis/Reporting

## 3. Key Components
### 3.1 Chart Generation Engine
- **`astro_chart_handler.py`**:
  - Handles `/chart` command processing
  - Implements full chart generation pipeline
  - Integrates with Telegram bot for user interaction
  - Manages YAML file generation and chart wheel rendering

- **`astrochart_cli_tool.py`**:
  - CLI tool for chart generation
  - Orchestrates input loading and output saving
  - Integrates with `astrochart_cli_engine` for core calculations

### 3.2 Position Calculator
- **`astro_position.py`**:
  - Swiss Ephemeris wrapper for planetary positions
  - Implements geolocation resolution
  - Supports multiple output formats (JSON, CSV, table)
  - Calculates house cusps and angles

### 3.3 Data Pipeline
- **`astro_loader.py`**:
  - Parses consolidated JSON chart data
  - Implements upsert logic for database operations
  - Normalizes data across 14+ PostgreSQL tables

- **`chart_pipeline.py`**:
  - Automates birth time sourcing from astrotheme.com
  - Integrates web scraping and database updates
  - Implements full chart generation workflow

### 3.4 Data Model
- **`astro_schema.sql`**:
  - Defines 14 normalized tables for natal chart data
  - Establishes relationships through foreign keys
  - Includes audit and pattern detection tables

### 3.5 Reference Data
- **`aspects.json`**:
  - Defines 7 major astrological aspects
  - Specifies angles, orbs, and interpretations
  - Used for chart analysis and interpretation

- **`elements.json`**:
  - Contains elemental data for zodiac signs
  - Provides keywords, meanings, and examples
  - Used for chart interpretation and analysis

## 4. Design Patterns
- **Factory Pattern**: 
  - `parse_chart_request()` in `astro_chart_handler.py` creates structured data objects
  - `load_input_data()` in `astrochart_cli_tool.py` handles multiple input formats

- **Singleton Pattern**:
  - Logging module (`logging`) used consistently across components
  - Configuration objects for database connections

- **Command Pattern**:
  - CLI tools implement command-line interface patterns
  - `main()` functions act as command coordinators

- **Pipeline Pattern**:
  - Chart generation follows a sequential processing pipeline
  - Data flows through parsing → calculation → storage → analysis stages

- **Idempotent Operations**:
  - `upsert_chart()` in `astro_loader.py` ensures data consistency
  - Script re-runs maintain data integrity

## 5. Data Model
The module maintains a comprehensive PostgreSQL schema with the following key tables:

| Table Name | Description |
|------------|-------------|
| `astro_natal_charts` | Master chart records with metadata |
| `astro_chart_objects` | Planetary positions and data |
| `astro_chart_points` | Angles (Ascendant, Midheaven, etc.) |
| `astro_natal_house_cusps` | House cusp positions |
| `astro_natal_aspects` | Calculated aspects between celestial bodies |
| `astro_arabic_parts` | Calculated lots/Arabic parts |
| `astro_dignities` | Essential dignities of planets |
| `astro_retrogrades` | Retrograde planets |
| `astro_fixed_star_conjunctions` | Planets conjunct fixed stars |
| `astro_geometric_patterns` | Geometric patterns (Grand Trines, etc.) |
| `astro_geometry_audit` | Pattern detection audit data |
| `astro_balance` | Elemental balance analysis |
| `astro_sect` | Day/night sect determination |
| `chart_ruler` | Chart ruler information |

- `astrochart_cli_tool.py`:
  - `-f` for input file
  - `--prefix` for output directory
  - Supports both file-based and flag-based input

## 7. Dependencies
### 7.1 External Libraries
- **Ephemeris**: `swisseph` for planetary position calculations
- **Geolocation**: `geopy` for location resolution
- **Timezone**: `timezonefinder` for timezone determination
- **Database**: `psycopg2` for PostgreSQL operations
- **Rendering**: `cairosvg` for chart wheel generation
- **Data Processing**: `yaml`, `json`, `re` for data handling

### 7.2 Internal Modules
- `astrochart_cli_engine.py` for core chart generation
- `astro_loader.py` for database operations
- `astro_chart_handler.py` for user interaction
- `chart_pipeline.py` for automated data sourcing

### 7.3 System Requirements
- PostgreSQL 12+ with proper schema
- Swiss Ephemeris data files
- Internet access for geolocation and external APIs
- Python 3.8+ with required dependencies

## 8. Configuration
### 8.1 Environment Variables
- `SWISSEPH_PATH`: Path to Swiss Ephemeris data files
- `ASTRO_DIR`: Base directory for chart files
- `CHARTS_DIR`: Directory for generated chart outputs
- `REQUEST_TIMEOUT`: Timeout for web requests (used in `chart_pipeline.py`)

### 8.2 Configuration Files
- `aspects.json`: Astrological aspect definitions
- `elements.json`: Elemental data for zodiac signs
- `astro_schema.sql`: Database schema definition

### 8.3 Runtime Configuration
- Command-line flags for `astro_position.py` and `astrochart_cli_tool.py`
- Constants in source files (e.g., `ASTROTHEME_URL`, `PERSON_ORDER` in `astro_report.py`)
- Database connection parameters in `CONN_PARAMS` (used in `astro_report.py`)

### 8.4 Geolocation Configuration
- `geopy` uses default geocoding services
- `timezonefinder` requires geographic data files
- Custom geolocation providers can be integrated through configuration
