# Mythos Root / Miscellaneous Module Overview

---

## 1. Module Purpose  
The **Root / Miscellaneous** module serves as a catch-all for utility, configuration, and maintenance components in the Mythos system. It handles tasks such as:
- Model version overrides and configuration
- File management and document processing
- Logging and patch management
- Codebase exports and diagnostics
- Database schema definitions
- External service integrations (e.g., Plaid, Telegram)
- System-level scripting for data reset and inspection

This module supports cross-cutting concerns and provides foundational tools for system administration, diagnostics, and integration with external services.

---

## 2. Architecture Overview  
The module is a heterogeneous collection of scripts, configuration files, and utility code. Key architectural elements include:

### **Data Flow**
1. **Configuration**: `.model_overrides.json` maps model IDs to versions, which is read during model initialization.
2. **File Processing**: `doc_manager.py` provides a TUI for managing versioned files and exporting them via LLM renaming.
3. **Patch Monitoring**: `mythos_patch_monitor.py` watches the `~/Downloads` directory for artifacts (patches, sales data) and triggers Git operations or notifications.
4. **Database Schema**: `mythos_schema.sql` defines PostgreSQL tables and triggers for financial, inventory, and user data.
5. **System Utilities**: Scripts like `export_mythos_codebase.sh` and `nuke_sales_data.sh` handle codebase exports and destructive data resets.

### **Component Interactions**
- **TUI (Text User Interface)**: `doc_manager.py` interacts with the file system and Ollama API for LLM-driven file renaming.
- **Git Integration**: `mythos_patch_monitor.py` uses `GitManager` to manage versioning and snapshots.
- **Database Integration**: `mythos_schema.sql` defines tables used by the sales ingestion and financial tracking subsystems.
- **External APIs**: `plaid_link.html` integrates with Plaid for bank account linking, while `mythos_patch_monitor.py` uses Telegram for notifications.

---

## 3. Key Components  
| Component | Role |
|----------|------|
| **`.model_overrides.json`** | Configuration file mapping model IDs to specific versions (e.g., `7811548479` → `iris-deep:latest`). |
| **`doc_manager.py`** | TUI application for managing versioned files, exporting latest versions, and LLM-driven renaming. |
| **`mythos_patch_monitor.py`** | Monitors `~/Downloads` for artifacts, handles Git versioning, and triggers Telegram notifications. |
| **`mythos_schema.sql`** | PostgreSQL schema defining tables for accounts, transactions, inventory, and user data. |
| **`export_mythos_codebase.sh`** | Bash script to export the Mythos codebase as a ZIP archive, excluding sensitive/generated files. |
| **`nuke_sales_data.sh`** | Script to reset sales-related data (database tables and file system directories). |
| **`plaid_link.html`** | UI component for linking bank accounts via Plaid's API. |

---

## 4. Design Patterns  
| Pattern | Usage |
|--------|-------|
| **Observer Pattern** | `mythos_patch_monitor.py` uses `FileSystemEventHandler` to monitor file system changes. |
| **Modal Screen** | `LabelInputScreen` in `doc_manager.py` captures user input for export labels. |
| **Singleton** | `DocManagerApp` in `doc_manager.py` acts as a singleton TUI instance. |
| **Procedural Scripting** | Bash scripts (e.g., `fix_logging_duplication.sh`, `inspect_sales_ingestion.sh`) follow linear, step-by-step logic. |
| **Visitor Pattern** | `fix_logging_duplication_safe.py` uses `ast` to parse and modify Python source code. |

---

## 5. Data Model  
### **PostgreSQL Tables** (from `mythos_schema.sql`)  
| Table | Purpose |
|-------|---------|
| `accounts` | Stores bank account metadata and balances. |
| `categories` | Transaction categories (e.g., "groceries", "utilities"). |
| `clothing_items` | Inventory of clothing items with attributes like material, color, and images. |
| `transaction_history` | Logs changes to transaction records (via trigger function). |
| `obligations` | Financial obligations (e.g., loans, subscriptions). |
| `chat_messages` | Stores user chat interactions. |

### **Triggers and Functions**  
- `log_transaction_change`: Logs changes to transaction fields (amount, category, status).
- `update_true_available_balance`: Recalculates account balances based on obligations.

## 8. Configuration  
### **Environment Variables**  
- `PGHOST`, `PGDATABASE`, `PGUSER`, `PGPORT`: PostgreSQL connection details.
- `OLLAMA_URL`: Base URL for the Ollama API.
- `TELEGRAM_BOT_TOKEN`: Telegram bot token for notifications.
- `GITHUB_PUSH_ENABLED`: Flag to enable/disable GitHub pushes.

### **Configuration Files**  
- `.model_overrides.json`: Model ID-to-version mappings.
- `.env`: Environment variables for database and API keys.
- `mythos_patch_monitor.service`: Systemd service configuration for the patch monitor.

### **Hardcoded Values**  
- `WATCH_DIR`: Directory monitored for artifacts (`~/Downloads`).
- `PATCH_DIR`: Directory for storing patches (`/opt/mythos/patches`).
- `ARTIFACT_PATTERNS`: Regex patterns for identifying artifact types.

## Summary  
The **Root / Miscellaneous** module is a critical utility layer in Mythos, enabling system administration, diagnostics, and integration with external services. It combines configuration files, scripts, and utility code to manage model versions, file processing, logging, and database schema. The module's design emphasizes flexibility and maintainability, leveraging patterns like the Observer and Singleton while relying on external services for key functionalities.
