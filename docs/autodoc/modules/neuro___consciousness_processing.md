# Mythos NEURO / Consciousness Processing Module Documentation

## 1. Module Purpose
The **Consciousness Processing** module in Mythos handles perception event routing, knowledge extraction, and grid-based consciousness layer processing. It enables:
- Categorization and logging of perception events
- Multi-layered knowledge extraction using LLMs
- Versioned processing of node-layer combinations
- Persistent storage and graph representation of extracted knowledge
- Real-time event streaming for downstream processing

## 2. Architecture Overview
![Architecture Diagram](https://via.placeholder.com/800x400?text=Consciousness+Processing+Architecture)

**Key Flow:**
1. Perception events are logged via `PerceptionRouter` to PostgreSQL and Redis
2. Events trigger `PerceptionEngine` processing through 9x9 node-layer grid
3. Knowledge extractions are written to PostgreSQL and Neo4j via `KnowledgeWriter`
4. Processing metadata is tracked by `ManifestWriter` and `VersionRegistry`
5. Redis streams enable real-time event distribution
6. Correction rules in `corrections.yaml` refine template generation

## 3. Key Components

### 3.1 Event Handling
- **PerceptionRouter**: Dual-logs events to PostgreSQL and Redis
- **PerceptionEventTypes**: Centralized event type definitions
- **PerceptionPromptGenerator**: Creates node-specific prompts using templates

### 3.2 Processing Engine
- **PerceptionEngine**: 
  - Coordinates multi-layer processing
  - Uses Ollama API for LLM inference
  - Implements extraction validation
  - Manages knowledge writing lifecycle

### 3.3 Data Management
- **ManifestWriter**: Tracks processing history in PostgreSQL
- **VersionRegistry**: Manages node-layer versioning and activation status
- **KnowledgeWriter**: 
  - Deduplicates extractions
  - Synchronizes PostgreSQL and Neo4j
  - Manages notification status

### 3.4 Grid Management
- **GridGenerator**: 
  - Creates 9x9 node-layer templates
  - Applies correction rules from YAML
  - Manages template validation
- **CorrectionsEngine**: Applies domain-specific prompt refinements

## 4. Design Patterns
- **Singleton**: `PerceptionRouter`, `VersionRegistry`, `KnowledgeWriter` for resource management
- **Facade**: `PerceptionEngine` abstracts complex processing workflow
- **Factory**: `get_perception_prompt()` creates node-specific prompts
- **Template Method**: `PerceptionEngine.process()` defines processing workflow
- **Cache**: `VersionRegistry` uses in-memory cache for version data
- **Strategy**: Different node-layer processing strategies based on configuration

## 5. Data Model

### PostgreSQL Tables
| Table Name | Key Fields |
|------------|-----------|
| perception_log | source, content, timestamp, event_type |
| grid_processing_manifest | exchange_id, node, layer, status, version |
| knowledge_extractions | extraction_id, subject, content, confidence, domain |
| grid_version_registry | node, layer, current_version, active_status |

### Neo4j Graph
- **Nodes**: Exchange, Extraction, Subject
- **Relationships**: 
  - `EXTRACTED_FROM` (Extraction → Exchange)
  - `ABOUT` (Extraction → Subject)
  - `SUPERSEDED_BY` (Extraction → Extraction)

## 6. API Surface

### Public Methods
```python
# Event Handling
PerceptionRouter.log_event(event_type, content, source=None, metadata=None)

# Processing Engine
PerceptionEngine.process(user_message, assistant_response)

# Manifest Management
ManifestWriter.record_activation(exchange_id, node, layer)
ManifestWriter.get_exchange_manifest(exchange_id)

# Version Control
VersionRegistry.get_version(node, layer)
VersionRegistry.bump_version(node, layer, new_version)

# Knowledge Management
KnowledgeWriter.write(extraction)
KnowledgeWriter.supersede(old_id, new_id)
```

### Redis Streams
- `perception_events`: Real-time event distribution
- `knowledge_updates`: Notification stream for new extractions

- **LLM Service**: Ollama (LLM inference)

  - `corrections.yaml` for template refinement

## 9. Processing Workflow

1. **Event Ingestion**
   - PerceptionRouter logs event to PostgreSQL and Redis
   - Validates against EVENT_TYPES

2. **Grid Activation**
   - VersionRegistry checks node-layer status
   - GridGenerator applies correction rules
   - ManifestWriter records activation

3. **Knowledge Extraction**
   - PerceptionEngine generates prompts
   - Ollama API returns structured extractions
   - KnowledgeWriter handles deduplication and graph sync

4. **Post-Processing**
   - ManifestWriter updates processing status
   - VersionRegistry tracks version changes
   - Notification system triggers based on significance

## 10. Error Handling
- **Retry Logic**: 3 retries for database operations
- **Fallback Prompts**: Generated when template creation fails
- **Validation**: Schema checks for all extractions
- **Monitoring**: Processing stats available via `get_processing_stats()`
